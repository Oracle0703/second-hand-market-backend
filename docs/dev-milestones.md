# 开发里程碑建议（dev-milestones）

## 默认假设
1. 团队配置参考：前端 1-2 人、后端 1-2 人、测试 1 人（可兼职）。
2. 目标周期：6~8 周可交付本期范围（轻量订单版）。
3. 采用迭代交付，每个阶段结束可演示可运行版本。

## 1. 里程碑总览

| 阶段 | 周期建议 | 目标 |
| --- | --- | --- |
| M1 基础搭建 | 第 1 周 | 初始化前后端工程、基础中间件、数据库迁移框架 |
| M2 入驻与鉴权 | 第 2-3 周 | 完成注册、审核、登录闭环 |
| M3 商品管理 | 第 4-5 周 | 完成商品全生命周期管理与上传 |
| M4 轻量订单与审计 | 第 6 周 | 完成订单闭环、日志审计、仪表盘基础统计 |
| M5 联调验收与上线准备 | 第 7-8 周 | 完成 E2E、性能与安全检查、发布上线 |

## 2. 分阶段详细计划

## M1 基础搭建（第 1 周）
交付内容：
1. `frontend/` 初始化（React + TS + Vite + 路由 + 请求封装）。
2. `backend/` 初始化（Gin + GORM + 配置管理 + 中间件骨架）。
3. MySQL 迁移框架与基础表（管理员、商家、会话、文件）。
4. 统一响应体、错误码、request_id 与日志格式。

验收标准：
1. 前后端本地一键启动成功。
2. 健康检查接口可用。
3. 基础鉴权中间件可解析 token 并识别角色。

## M2 入驻与鉴权（第 2-3 周）
交付内容：
1. 商家注册页与注册接口。
2. 管理员审核列表/详情/通过/驳回页面与接口。
3. 登录、刷新令牌、退出登录全链路。
4. 注册状态页与驳回重提功能。

验收标准：
1. 可完整跑通 `注册 -> 审核 -> 登录`。
2. 未审核商家禁止登录。
3. 审核动作均有审计日志。

## M3 商品管理（第 4-5 周）
交付内容：
1. 商品列表、新建、编辑、详情页。
2. 商品 API：创建、编辑、列表、详情、上架、下架、关闭。
3. 图片上传链路（presign + confirm）与前端上传组件。
4. 移动端适配（商品核心流程）。

验收标准：
1. 商品状态机按规则运行，无非法流转。
2. 列表筛选与分页一致性通过联调。
3. 移动端可完成商品创建与上下架。

## M4 轻量订单与审计（第 6 周）
交付内容：
1. 订单列表、详情页面与完成/关闭操作。
2. 订单 API：创建、详情、列表、完成、关闭。
3. 商品与订单状态联动事务。
4. 平台与商家日志查询页。

验收标准：
1. 可跑通 `发布商品 -> 上架 -> 创建订单 -> 成交/关闭`。
2. 订单完成后商品自动转 `SOLD`。
3. 状态变更接口审计覆盖率 100%。

## M5 联调验收与上线准备（第 7-8 周）
交付内容：
1. 全链路 E2E 用例与回归清单。
2. 性能压测（重点：登录、商品列表、审核列表）。
3. 安全检查（鉴权、限流、输入校验、日志脱敏）。
4. 部署脚本、配置模板、上线回滚预案。

验收标准：
1. P0/P1 缺陷清零后发布。
2. 上线后关键指标监控可用（错误率、接口耗时、登录成功率）。
3. 回滚演练通过。

## 3. 测试策略建议
1. 单元测试：
   - 状态机流转
   - 权限判断
   - 参数校验
2. 集成测试：
   - 注册审核登录主流程
   - 商品全流程
   - 订单状态联动
3. 前端 E2E：
   - 关键页面可达
   - 表单提交流程
   - 移动端关键路径

## 4. 风险与缓冲建议
1. 风险：需求边界膨胀（被拉入支付、买家端）。  
   建议：严格执行本期范围清单，新增需求进入下一迭代。
2. 风险：移动端适配晚介入导致返工。  
   建议：M3 即并行验收移动端页面。
3. 风险：状态机实现分散。  
   建议：后端单点维护状态流转规则并加测试门禁。

## 5. 发布门禁（Go-Live Checklist）
1. 所有 API 文档与实现一致。
2. 数据迁移脚本可重复执行（幂等）。
3. 关键链路日志可追踪到 request_id。
4. 关键页面在 PC 和移动端均通过验收。
5. 线上配置与密钥完成环境隔离。
