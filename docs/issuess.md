## 一、订单与商品闭环不完整，需要补齐

### 问题
当前文档中“轻量订单”与“商品状态”之间的关系不够严密，存在歧义：
- 创建订单时，商品是否应该继续可售？
- 同一商品是否允许多个 `CREATED` 订单同时存在？
- 订单关闭后商品到底回到什么状态？
- 当前文档里 `close` 后“由商家自行处理商品状态”，这会导致实现层不一致

### 修改要求
请明确以下内容，并形成完整闭环：
1. 商品是否支持“被订单占用/预占”状态  
   - 如果支持，请补充状态（如 `LOCKED` / `RESERVED`）
   - 如果不支持，请明确“订单仅用于成交登记，不承担库存锁定”
2. 同一商品是否允许多个未完成订单并存
3. 订单关闭后商品状态如何处理
4. 订单完成与商品 `SOLD` 的事务一致性规则
5. 给出一套清晰、可实现的商品-订单状态联动表

### 需要更新的文件
- `docs/specs.md`
- `docs/backend-api-checklist.md`
- `docs/data-model.md`

## 二、商品状态下的可编辑规则不够明确

### 问题

这会导致前端、后端对“哪些字段能改”理解不一致。

### 修改要求
请补一张明确规则表，至少说明：
- `DRAFT`
- `ON_SHELF`
- `OFF_SHELF`
- `SOLD`
- `CLOSED`

每种状态下：
1. 哪些字段允许编辑
2. 哪些字段禁止编辑
3. 哪些操作允许执行（上架/下架/关闭/成交）
4. 是否需要前端禁用按钮 + 后端二次校验

### 需要更新的文件
- `docs/specs.md`
- `docs/frontend-pages.md`
- `docs/backend-api-checklist.md`
