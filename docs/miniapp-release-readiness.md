# 买家小程序发布前收口

更新时间：2026-09-12
状态：微信/抖音代码构建已通过；平台和真机验收待签收

## 1. 当前已交付能力

1. 首页、分类、搜索、商品列表/详情、收藏、浏览历史、登录、我的、门店指南和意向页面。
2. 商品数据按 `merchant_no` 隔离；旧客户端缺失商户号时由后端 `BUYER_DEFAULT_MERCHANT_NO` 临时兼容。
3. 游客收藏/历史和登录后 guest merge；微信/抖音登录后端支持 `mock/real/disabled`。
4. 商品详情当前以直接电话联系为主；意向 API 和商家后台处理页保留，意向入口可按产品配置隐藏。
5. 门店导航使用 `Taro.openLocation` 固定坐标；电话使用 `Taro.makePhoneCall`。
6. 抖音端处理 `tt.onNeedPrivacyAuthorization` 与隐私授权弹窗，授权后通过真实点击继续发起电话；不以本地缓存冒充平台授权状态。

## 3. 发布前平台门禁

### 微信

- 配置有效 `request`、图片和业务域名以及 HTTPS 证书。
- 使用真实 `wx.login` code 验证 `BUYER_WECHAT_LOGIN_MODE=real`；生产禁止 `mock`。
- 真机验证游客资产合并、收藏/历史、图片、分享、电话和导航。

### 抖音

- 在开发者平台声明并审核 `tt.makePhoneCall`、位置相关能力及隐私协议。
- 测试版和正式版分别确认隐私声明已生效；首次授权、已授权再次点击、用户撤回授权三种路径都要验证。
- 真机检查 `NODE_ENV`、API 域名、图片域名和分包/资源加载，确认首页不会停留在 loading。

## 4. 真机验收清单

1. 冷启动 -> 首页 -> 分类 -> 搜索 -> 详情。
2. 游客收藏和浏览历史，登录后数据不丢失、不重复。
3. 在售、下架、锁定、售罄商品的状态文案和联系按钮符合规格；非在售商品不显示可购买电话入口。
4. 已授权用户连续两次拨打电话；未授权用户完成授权后立即拨号；拒绝/撤回授权显示可恢复提示。
5. 门店导航、分享落地和弱网失败重试。
6. iOS 与 Android 至少各一台，微信与抖音分别保留日志或录屏证据。

## 5. 发布判断

当前结论：**代码可进入测试版验收，不直接判定生产可发布**。

真实平台凭据、隐私协议审核、合法域名、证书和真机证据完成后，才可切换生产登录模式并提交平台审核。任何平台能力变更都要同步更新本文件和 [产品与系统规格](specs.md)。
