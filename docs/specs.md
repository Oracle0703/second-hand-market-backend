# 产品 Specs / 目标文档（specs）

## 默认假设
1. 本文以 `PlatformAdmin` 与 `MerchantOwner` 为当前生效角色。
2. 订单仅用于记录成交过程，不承载支付。
3. 商家审核通过是登录前置条件。
4. 商品状态与订单状态以本文状态机为唯一准则。

## 1. 产品目标

### 1.1 业务目标
1. 将商家入驻周期标准化并可追踪。
2. 将商家商品管理流程产品化，减少线下沟通成本。
3. 为后续订单、财务、子账号扩展建立稳定接口基础。

### 1.2 成功指标（本期）
1. 商家注册后 5 分钟内可在管理员审核列表中检索到。
2. 审核通过后商家登录成功率 >= 99%（排除密码错误）。
3. 商品发布到上架流程可在 3 分钟内完成（中位时间）。
4. 商品管理与订单关键操作审计覆盖率 100%。
5. 移动端核心流程（登录、商品新增、上下架）完成率 >= 95%。

## 2. 用户与核心场景

### 2.1 平台管理员（PlatformAdmin）
1. 审核商家资质并给出通过/驳回理由。
2. 查看商家经营状态（商品数量、上架数、成交数）。
3. 回溯关键操作日志，处理异常行为。

### 2.2 商家主账号（MerchantOwner）
1. 完成注册并跟踪审核结果。
2. 管理商品全生命周期（草稿、上架、下架、成交、关闭）。
3. 创建并维护轻量订单状态。

## 3. 功能规格

## 3.1 认证与账号
1. 商家注册：
   - 输入企业名、联系人、手机号、登录账号、密码、营业执照图片。
   - 提交后创建商家与主账号，审核状态 `PENDING`。
2. 登录：
   - 仅 `APPROVED` 商家允许登录。
   - 返回 `access_token`、`refresh_token`、用户信息、权限集合。
3. 令牌刷新与退出：
   - 支持刷新 token。
   - 退出登录后当前 refresh token 失效。

## 3.2 商家审核
1. 审核列表支持筛选：状态、时间区间、关键词（商家名/联系人/手机号）。
2. 审核详情展示：基础资料、证照图片、历史审核记录。
3. 审核动作：
   - 通过：状态改为 `APPROVED`。
   - 驳回：状态改为 `REJECTED`，需填写驳回原因。

## 3.3 商品管理
1. 创建商品：标题、描述、分类、价格、成色、库存、图片。
2. 编辑商品：仅限 `DRAFT`/`OFF_SHELF`，`ON_SHELF` 可改非关键字段（如描述、图片）。
3. 状态操作：上架、下架、关闭、标记成交。
4. 商品列表：
   - 支持状态筛选、关键词搜索、时间排序、分页。
   - PC 默认表格；移动端默认卡片。

## 3.4 轻量订单
1. 创建订单：针对单个商品创建成交记录，记录成交价与备注。
2. 完成订单：订单 `CREATED -> COMPLETED`，商品转为 `SOLD`。
3. 关闭订单：订单 `CREATED -> CLOSED`，商品状态保持原逻辑（通常回到 `ON_SHELF` 或 `OFF_SHELF`，以商家手动决策为准）。

## 3.5 审计与日志
1. 关键操作必须写日志：
   - 审核通过/驳回
   - 商品创建/编辑/上下架/关闭/标记成交
   - 订单创建/完成/关闭
2. 日志内容：操作人、角色、对象、前后状态、结果、时间、请求标识。

## 4. 关键流程规格

## 4.1 注册 -> 审核 -> 登录
1. 商家提交注册后，系统返回“待审核”状态。
2. 待审核与驳回状态禁止登录。
3. 审核通过后登录成功并进入商家首页。

## 4.2 发布商品 -> 上下架 -> 成交/关闭
1. 商家创建商品默认 `DRAFT`。
2. 满足必填字段后允许上架至 `ON_SHELF`。
3. 可下架到 `OFF_SHELF`，再上架。
4. 通过订单完成将商品置 `SOLD`；或直接关闭为 `CLOSED`。

## 5. 状态机定义

## 5.1 商家审核状态机

| 当前状态 | 目标状态 | 触发动作 | 触发角色 | 规则 |
| --- | --- | --- | --- | --- |
| `PENDING` | `APPROVED` | 审核通过 | PlatformAdmin | 必须记录审核人和时间 |
| `PENDING` | `REJECTED` | 审核驳回 | PlatformAdmin | 必须填写驳回原因 |
| `REJECTED` | `PENDING` | 重新提交资料 | MerchantOwner | 变更后重新进入审核 |

## 5.2 商品状态机

| 当前状态 | 目标状态 | 触发动作 | 触发角色 | 规则 |
| --- | --- | --- | --- | --- |
| `DRAFT` | `ON_SHELF` | 上架 | MerchantOwner | 必填字段齐全 |
| `ON_SHELF` | `OFF_SHELF` | 下架 | MerchantOwner | 即时生效 |
| `OFF_SHELF` | `ON_SHELF` | 重新上架 | MerchantOwner | 字段仍合法 |
| `ON_SHELF` | `SOLD` | 标记成交/订单完成 | MerchantOwner | 需关联订单记录 |
| `ON_SHELF`/`OFF_SHELF`/`DRAFT` | `CLOSED` | 关闭商品 | MerchantOwner | 关闭后不可恢复 |

## 5.3 订单状态机

| 当前状态 | 目标状态 | 触发动作 | 触发角色 | 规则 |
| --- | --- | --- | --- | --- |
| `CREATED` | `COMPLETED` | 完成订单 | MerchantOwner | 商品变更为 `SOLD` |
| `CREATED` | `CLOSED` | 关闭订单 | MerchantOwner | 需填写关闭原因（可选） |

## 6. 非功能规格
1. 鉴权：JWT + Refresh Token，access token 过期默认 2h，refresh token 默认 7d。
2. 错误码：统一业务错误码，前后端共享字典。
3. 日志审计：所有状态变更接口必须写审计日志。
4. 分页筛选：统一 `page/page_size/total/items`。
5. 图片上传：限制类型（jpg/png/webp）、大小（单图 <= 5MB）、数量（单商品 <= 9 张）。
6. 移动端适配：最小支持宽度 360px，关键功能无横向滚动阻塞。
7. 可维护性：模块分层、统一 DTO、接口文档与实现同版本维护。

## 7. 验收标准（关键用例）
1. Given 商家处于 `PENDING`，When 使用正确密码登录，Then 返回“审核未通过不可登录”错误码。
2. Given 管理员审核通过商家，When 商家再次登录，Then 登录成功并返回 token。
3. Given 商品为 `DRAFT` 且必填项不全，When 发起上架，Then 返回参数校验错误。
4. Given 商品为 `ON_SHELF`，When 商家执行下架，Then 状态变更为 `OFF_SHELF` 且写入日志。
5. Given 订单为 `CREATED`，When 商家完成订单，Then 订单变更 `COMPLETED` 且商品变更 `SOLD`。
6. Given 非法状态流转（如 `SOLD -> ON_SHELF`），When 调用接口，Then 返回状态流转错误码。

## 8. 版本边界
1. 本期不做支付、退款、售后和买家订单展示。
2. 子账号与 RBAC 只保留设计接口，不做可用功能。
3. 后续版本优先方向：子账号权限、订单扩展字段、运营报表。
